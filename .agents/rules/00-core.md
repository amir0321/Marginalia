# Marginalia – core rules (always apply)

## What this is
Marginalia is a personal book library and favorite-quotes app, built as an internship coding test.
Users register, log in (JWT), manage their own books (CRUD) and up to 5 favorite quotes ("Mina citat").
Must be responsive, use Bootstrap + Font Awesome and be published online. Dark/light mode is an optional extra.
Monorepo: api/ = .NET 9 Web API, web/ = Angular 20, docs/ = design handbook and decisions.
Source of truth for design and UI text: `docs/design-system.md` & `docs/design/` (summarized in `21-design.md`).

## Stack (fixed – do not swap or add alternatives)
- Frontend: Angular 20 (never newer), standalone components, signals, SCSS, Bootstrap 5.3, Font Awesome (free),
  ng-bootstrap, @fontsource Inter + Fraunces.
- Backend: .NET 9, ASP.NET Core controllers, EF Core 9, PostgreSQL via Npgsql, JWT bearer.
- Hosting: Netlify (frontend, proxies /api), Render via Docker (API), Neon (PostgreSQL).
- Local: docker compose Postgres 17, API on http://localhost:5080, Angular on http://localhost:4200.
- No other UI libraries (no Angular Material, Tailwind, jQuery) and no state libraries (no NgRx).
  No new dependency without stating why and getting approval.

## Architecture decisions (already made)
- Same-origin via proxy: Angular dev proxy (proxy.conf.json) in development, Netlify rewrite in production.
  The API has NO CORS configuration. Never add AddCors/UseCors. Never hard-code API hosts in the frontend.
- Data is per user. Books and quotes belong to the logged-in user; the user id comes from the JWT "sub" claim.
- Max 5 quotes per user, enforced in the API (409) and reflected in the UI.
- Tokens: JWT, 60 minutes, no refresh token, stored in localStorage under "marginalia.token".
- Free hosting sleeps: the UI wakes the API via /api/health and shows a waiting message.

## RedRiver Coding Test Requirements (Hard Acceptance Criteria)
Every implementation step must strictly adhere to and fulfill these criteria:
1. **Books CRUD**:
   - List view showing all user's books.
   - Main page has "Lägg till ny bok" button.
   - Clicking "Lägg till ny bok" navigates to form (title, author, published date).
   - On submit: redirects back to book list, showing the newly added book.
   - Each book has "Redigera" button navigating to edit form; on submit redirects back showing updated book.
   - Each book has "Radera" button allowing deletion; on delete book is removed from list.
2. **JWT Token Management**:
   - Authentication with JWT tokens (generated by .NET 9 API, verified on endpoints).
   - Simple login page for username and password.
   - Registration page for new users, which can then be used to log in.
   - On login, backend issues JWT; frontend stores securely in localStorage under "marginalia.token" and attaches to subsequent requests.
   - Backend enforces token validation on all CRUD operations.
3. **Mina citat**:
   - Dedicated view named "Mina citat".
   - Displays list of favorite quotes (enforce limit of 5 quotes).
   - Users can add, edit, and delete quotes.
   - Navigation menu allows switching between books view and quotes view.
4. **Responsive Design**:
   - Layout and components adapt smoothly across desktop, tablet, and mobile (tested at 390 px and 1440 px).
   - Navigation menu collapses to a responsive hamburger menu on smaller screens (< 992 px).
   - Form fields, buttons, alignment, and spacing adjust properly.
5. **Bootstrap & Font Awesome**:
   - Bootstrap 5.3 for layout, buttons, forms, cards, modals, dropdowns.
   - Font Awesome icons throughout the application.
6. **Bonus Challenge (Ytterligare utmaning)**:
   - Toggle button allowing users to switch between Light and Dark UX design.
7. **Submission**:
   - Published on free hosting (Netlify for frontend, Render for API, Neon PostgreSQL).
   - Live URL and GitHub repository link.

## Scope control
- Priority: Must → Should → Could.
  Must: auth, books CRUD, quotes CRUD (max 5), menu, responsive layout, Bootstrap + Font Awesome, deployment.
  Should: search/sort, shared delete modal, toasts, 401/404 handling, show/hide password.
  Could (last): character counter, password strength, skeleton loaders.
- Won't build: design-guide page, e-mail field, status badges, roles, password reset, pagination.
- Do only what the current task asks. No drive-by refactors, no extra features, no renames of unrelated code.
